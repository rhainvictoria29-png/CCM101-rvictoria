# Mission Reflection

Automation is important when managing hundreds of cloud servers because it makes repetitive tasks faster, easier, and more consistent. Instead of manually performing the same operations on every server, administrators can use scripts and scheduled tasks to handle them automatically. This saves time, reduces manual work, and helps prevent human errors. Through this activity, I learned how a simple Bash script can automate backup operations and make system administration more efficient.

However, automation also has risks, especially when a mistake is included in a script or command. For example, a small typo in an automated command could affect 1,000 servers at the same time, potentially deleting important files or disrupting services. This shows that automation should not be used without proper checking and testing. Administrators must review their scripts, test them in a safe environment, and make sure they have backup and recovery plans before applying changes on multiple servers.

The Bash script I created in this mission was different from the Docker Compose YAML used in Mission 6. Bash is a scripting language that allows commands to be executed to perform tasks such as creating directories, managing files, and generating backups. On the other hand, Docker Compose uses YAML configuration files to define and manage multiple containers and their services. Both are useful in cloud computing, but they serve different purposes in automating tasks and managing applications.

Throughout Laboratories 1–9, my understanding of cloud computing developed from learning its basic concepts to performing practical activities involving cloud services, virtualization, containers, networking, security, and automation. I realized that cloud computing is not only about storing data or accessing resources through the internet. It also involves managing infrastructure, maintaining security, deploying applications, and making systems more efficient through different technologies and tools.

Among the different roles, I enjoyed the Infrastructure Engineer role the most because it involves managing systems, servers, and the resources needed to keep services running. I found the activities related to system administration, Linux commands, and automation interesting because they allowed me to perform practical tasks and understand how infrastructure works. This mission helped me appreciate how important automation is in maintaining reliable and efficient cloud environments.
